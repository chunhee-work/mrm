# web/ decisions

- Stack as in plan.md §3: Next.js 15 App Router, Drizzle on Neon (neon-http), Better Auth (email+password, verification, reset), Resend, Vercel Blob.
- Blobs are uploaded with `access: "private"` under `<orgId>/…` (files hold NRIC/addresses). The upload route rejects paths outside the caller's org.
- Org is created at sign-up by a Better Auth `user.create.after` hook (neon-http has no transactions; two inserts).
- Password minimum 10 chars; email verification required before login.
- `src/db/index.ts` is lazy so `next build` works without secrets; a localhost DATABASE_URL uses node-postgres (tests only).
- Migrations: `drizzle/*.sql` (generated by drizzle-kit), applied by `npm run db:migrate` (tracks `_migrations`).
- Stage-2 tables (merimen_connections, jobs, usage, credits) are created now so the schema is stable; nothing uses them yet.
- Privacy/terms pages are placeholders; owner supplies legal text.
- Brand name: **Autopilotclaim** (owner, 2026-11-14; domain autopilotclaim.com bought, DNS on Vercel). Mail is sent from `EMAIL_FROM="Autopilotclaim <noreply@autopilotclaim.com>"` once the Resend domain is verified (until then use the Resend test sender). The test sender only delivers to the Resend account owner's own email address, so only that address can complete sign-up in production for now.
- No domain will be bought for now (owner, 2026-11-14): deploy on the default *.vercel.app URL.

## Smoke test account (2026-11-14)
- Pattern copied from chunhee00/oeru-onhand (`staging` branch, docs/smoke.md): real browser, every page in EN/BM/中文 on laptop and phone, target guard (only our own site or localhost), PASS/WARN/FAIL report. Unlike oeru-onhand (signed-out only; its smoke account was cancelled), Autoclaim has login, so it also logs in.
- Account: `smoke-tester@autoclaim.invalid`, email pre-verified (no mail needed), own empty org. Created with `scripts/seed-smoke-user.ts` (idempotent, touches only that email). Password lives only in the CI/local env `SMOKE_PASSWORD`, never in the repo.
- Run: `SMOKE_PASSWORD=… node scripts/smoke.mjs https://autoclaim-web.vercel.app` (needs Playwright). It writes nothing, uploads nothing.
- Not done yet: a GitHub Actions workflow (needs `SMOKE_PASSWORD` as a repo secret, and a workflow file the owner approves).

## Two colour sets (2026-11-15)
- Owner's rule: only the landing is dark ("Night Bay"); every app/workspace page is white. So the colour tokens in `tailwind.config.ts` are CSS variables with two sets in `globals.css`: the dark set on `:root` (landing, public site pages, 404) and a white set under `.theme-light`. `components/app-layout.tsx` (case list, new case, billing) and `components/auth-layout.tsx` (log in, sign up, password reset) wrap themselves in `.theme-light`; their route layouts export `lightViewport` from `lib/theme.ts`.
- A new signed-in page gets the white set by using `AppLayout`. Use the tokens (`bg-panel`, `text-fg`, `border-hair`, `bg-ice text-bay` for the primary action…), never a hex colour, so it follows the set it sits in.
- On white, the primary colour (`ice`) is ink black and the scan blue (`scan`) is the accent (progress, the lit top edge of a sheet). The logo's visor is filled in on white so its two white eyes stay visible.
- `public/landing/bay-*.jpg` were rendered again with `scripts/landing-posters.mjs`: they now show the white face ball, like the live 3D scene.

## Admin backoffice (plan: issue #4)
- Lives at `/admin` on app.autopilotclaim.com (not a separate host). A `backoffice.` alias can be added later as a Vercel domain plus a host rewrite.
- Access: verified email listed in env `ADMIN_EMAILS` (comma list; missing/empty/malformed = nobody) and a session younger than 12 h. Everyone else gets the same 404 as any missing page. No `/api/admin/*` routes exist; all reads happen in server components.
- Internal accounts (smoke account, `ADMIN_EMAILS`, `ADMIN_EXCLUDE_EMAILS`) are left out of every number unless `?internal=1`.
- Every Claude call goes through `trackedParse()` in `lib/claude.ts` and lands in `llm_calls` (one row per billed response, unique `request_id`; failures get `ok=false`). Prices live in `lib/pricing.ts` (`PRICES`); an unknown model is stored unpriced, never guessed. Update `PRICES` when `CLAUDE_MODEL` changes.
- `email_log` stores kind, recipient domain and outcome only.
- Org-wide spend comes from the Anthropic Admin API (`ANTHROPIC_ADMIN_KEY`), best-effort cached per instance. The response shape was written from the docs and is tested against mocks; confirm it against the first real response.
- Tests: `npm test` runs unit tests anywhere; the seeded database tests run only when `DATABASE_URL` points at a local Postgres with the migrations applied.

## Two hosts, one deployment (2026-11-15)
- The system is on the app host (env `BETTER_AUTH_URL`, `https://app.<domain>`); the bare domain and `www.` are the marketing site. Better Auth refuses a sign-in posted from the bare domain (wrong origin, 403) and a session made on one host does not exist on the other.
- So `src/middleware.ts` sends log in, sign up, password reset, the case pages, billing and admin asked for on the bare domain to the same path on the app host (`lib/hosts.ts`, tested), and the public top bar and the landing's Sign up button link straight to the app host there. Previews (`*.vercel.app`) and localhost are left alone. No new env variable.
- Case list (owner, 2026-11-15): one line per case. A case that stopped reads "On hold" and has no button (the team picks it up); the words "Try again" and "rejected" are not shown to users.
- Dates a signed-in page prints are formatted in `Asia/Kuala_Lumpur`, so the server and the browser write the same day.
